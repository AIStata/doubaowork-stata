## **01 · 一、为什么是豆包工作**

AI 进入计量实证有四条路：L1 帮你写代码，L2 陪你跑代码，L3 自己会跑，**L4 让一组 AI 替你跑，而你还在跟人讨论下一步怎么做**。

豆包工作 + AIStata MCP / Stata-Kernel-Jupyter 代表的就是 L4——**组织级调度**：

- 委派

  ：主会话把可独立完成的子任务一次性下发；

- 并行

  ：后台子智能体各跑各的 Stata，互不阻塞；

- 校验

  ：汇总智能体检查 log、符号、样本量，机器可判定；

- 交付

  ：do、log、图、结果行、汇总矩阵，五件齐全才算交付。

价值不在"模型更强"，而在**时间结构变了**：等待从"盯着屏幕"变成"后台推进"，你可以一边等 200 次置换检验，一边跟合作者讨论识别策略。
